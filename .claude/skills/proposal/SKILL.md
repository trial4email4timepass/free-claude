# Client Proposal

## Goal
Produce a professional, specific proposal document — clear scope, deliverables, and value — that a client could sign off on as-is.

## Inputs to gather (ask only if truly missing)
- Client/project context and what they need
- Scope of work and deliverables (or help the user define them if vague)
- Timeline and pricing/investment (if the user wants it included)

## Workflow
1. Open with a brief statement of the client's situation/goal, in their language — shows the proposal was written for them, not templated.
2. Define scope and deliverables specifically and concretely — vague deliverables cause scope disputes later.
3. State the value/outcome the client gets, tied to their stated goal, not just a list of tasks performed.
4. Include timeline and pricing/investment if provided; if not provided, leave a clearly marked placeholder rather than inventing numbers.
5. Close with clear next steps to move forward (approval, signature, kickoff date).

## Output template
```markdown
# Proposal: <project name> for <client>

## Overview
<client's situation and goal, briefly>

## Scope & Deliverables
- <deliverable 1> — <what it includes>
- <deliverable 2> — <what it includes>

## Value
<outcome tied to the client's goal>

## Timeline
<schedule, or milestones>

## Investment
<pricing, or "[to be confirmed]" if not provided>

## Next Steps
<how to proceed>
```

## Avoid
- Vague deliverables that invite scope creep
- Inventing pricing/timeline numbers the user didn't provide
- A proposal that reads like a generic template with the client's name swapped in
