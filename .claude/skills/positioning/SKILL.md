# Positioning

## Goal
Produce a sharp, defensible positioning statement and supporting rationale — not a vague mission statement.

## Inputs to gather (ask only if truly missing)
- Product/brand and what it does
- Target audience (reuse `audience` skill output if available)
- Key competitors/alternatives (reuse `competitor` skill output if available)

## Workflow
1. Identify the category the product competes in — and whether claiming an existing category or creating a new one is the right call.
2. Identify the single most differentiated, defensible benefit relative to alternatives — not a list of features, one sharp claim.
3. Write the positioning statement using the standard form: For [audience], [product] is the [category] that [key benefit], unlike [main alternative], [product] [key differentiator].
4. Stress-test it: would a competitor's positioning statement, with names swapped, sound identical? If so, sharpen it.
5. Note proof points that back the claim — positioning without evidence is just a slogan.

## Output template
```markdown
# Positioning: <brand/product>

**Category:** <category claimed>

**Positioning statement:**
For <audience>, <product> is the <category> that <benefit>, unlike <alternative>, <product> <differentiator>.

**Proof points:**
- <evidence 1>
- <evidence 2>

**Stress test:** <does this hold up against swapping in a competitor's name? note any weakness>
```

## Avoid
- Positioning that's really just a value proposition with no competitive contrast
- Claims with no supporting proof points
- Statements generic enough to apply to any competitor
