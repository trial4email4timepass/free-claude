# Competitor Analysis

## Goal
Produce an honest competitive analysis that identifies real gaps and openings — not a superficial feature checklist.

## Inputs to gather (ask only if truly missing)
- The user's product/business
- Known competitors (direct and, if relevant, indirect/substitute solutions)
- What decision this analysis will inform (positioning, pricing, feature roadmap)

## Workflow
1. List direct competitors and, briefly, indirect ones (substitutes/status quo the audience uses instead).
2. For each competitor, cover: what they do well, where they're weak or underserving customers, their apparent positioning/pricing, and any signal about who they target.
3. Identify patterns across competitors — a gap none of them address well is more valuable than a single competitor's weakness.
4. Translate findings into implications: what this means for the user's positioning or roadmap, not just a data dump.

## Output template
```markdown
# Competitive Analysis: <market/category>

## <Competitor 1>
- Strengths: <list>
- Weaknesses: <list>
- Positioning/pricing: <summary>

## <Competitor 2>
...

## Patterns & gaps
<what's underserved across the market>

## Implications
<what this suggests for positioning/roadmap>
```

## Avoid
- A feature-comparison table with no interpretation
- Only listing competitors' strengths (weaknesses are the actionable part)
- Skipping the "so what" implications section
